# MySQL 面试速记卡

> 用法：面试前 30 分钟看一遍；遮住右列自问自答。
> 完整版：[MySQL-Study-Handbook.md](./MySQL-Study-Handbook.md)

## 如果只能记 10 条

1. 索引是 B+ 树：矮胖、有序、范围快。
2. 聚簇索引叶子存整行，二级索引叶子存主键；查索引外的列要回表。
3. 联合索引遵守最左前缀；等值在前，范围在后。
4. 查询列全在索引里叫覆盖索引，`Extra: Using index`。
5. 索引失效：函数、隐式转换、前导 `%`、OR、顺序不对、低选择性。
6. ACID：undo 原子、redo 持久、锁+MVCC 隔离、约束+应用一致。
7. MVCC：隐藏列 + undo 版本链 + ReadView；RC 每条语句新视图，RR 复用第一次。
8. InnoDB 行锁锁在索引上；没走索引会锁大量记录/间隙。
9. 死锁：固定加锁顺序、短事务、走索引、失败重试。
10. 分库分表是最后手段；分片键决定一切，跨片查询/事务/扩容是主要成本。

## 一、索引

| 问题 | 一句话答案 |
| --- | --- |
| 为什么用 B+ 树？ | 非叶子只存键、扇出大、树矮；叶子有序链表，范围/排序友好。 |
| 为什么不用 B 树？ | 非叶子存数据，扇出小、树高；范围查询跨层跳。 |
| 为什么不用哈希？ | 只支持等值，不支持范围、排序、最左前缀。 |
| 聚簇索引是什么？ | 主键索引，叶子存整行；一张表一个。 |
| 二级索引是什么？ | 叶子存主键值；查非索引列要回表。 |
| 回表是什么？ | 二级索引拿主键，再查聚簇索引取整行。 |
| 覆盖索引是什么？ | 查询列全在索引里，不回表，`Using index`。 |
| 最左前缀？ | 联合索引从最左列开始连续使用；`(a,b,c)` 中 `b=?` 用不上。 |
| 范围列后面的列？ | 一般不能继续用于定位/排序，最多 ICP 过滤。 |
| 索引失效？ | 列上函数、隐式转换、前导 `%`、OR、顺序不对、低选择性、表太小。 |
| 索引越多越好吗？ | 不是；占空间、写放大、优化器选择变多。 |
| 主键为什么自增？ | 顺序写入减少页分裂；UUID 随机写入碎片多、二级索引大。 |
| 深分页怎么优化？ | 游标 `WHERE id > last`；延迟关联；覆盖索引。 |
| EXPLAIN 看什么？ | type、key、rows、filtered、Extra。 |
| `type=ALL`？ | 全表扫描；检查索引、顺序、函数/转换、统计信息。 |
| `Using filesort`？ | 不能靠索引排序，额外排序；考虑调整索引顺序。 |
| `Using temporary`？ | 用了临时表，常见于 GROUP BY/DISTINCT/UNION。 |
| `varchar=123` 会怎样？ | 列被转成数字，索引可能失效。 |
| `LIKE 'abc%'` 能用索引吗？ | 能；`%abc` 不能有效使用。 |
| `IS NULL` 能用索引吗？ | 能，不要误答“NULL 不能建索引”。 |

## 二、事务

| 问题 | 一句话答案 |
| --- | --- |
| ACID 怎么实现？ | undo 原子、redo 持久、锁+MVCC 隔离、约束+应用一致。 |
| 隔离级别？ | RU、RC、RR、Serializable；MySQL 默认 RR。 |
| 脏读？ | 读到未提交数据。 |
| 不可重复读？ | 同一事务两次读同一行结果不同。 |
| 幻读？ | 同一事务两次范围查询，行数变了。 |
| RC 和 RR 的核心区别？ | ReadView 时机：RC 每条语句新建，RR 第一次快照读建并复用。 |
| MVCC 三要素？ | 隐藏列、undo 版本链、ReadView。 |
| ReadView 有什么？ | `m_ids`、`min_trx_id`、`max_trx_id`、`creator_trx_id`。 |
| 快照读 vs 当前读？ | 普通 SELECT 不加锁读历史版本；FOR UPDATE/UPDATE 等读最新并加锁。 |
| RR 解决幻读了吗？ | 快照读靠 MVCC，当前读靠 next-key；不是绝对。 |
| redo 和 binlog 区别？ | redo 是 InnoDB 物理日志，崩溃恢复；binlog 是 Server 逻辑日志，复制/归档。 |
| 两阶段提交？ | redo prepare → binlog 落盘 → redo commit。 |
| “双 1”？ | `innodb_flush_log_at_trx_commit=1` + `sync_binlog=1`。 |
| 长事务危害？ | 锁久、undo 膨胀、purge 延迟、主从延迟、可能阻塞 DDL。 |
| `@Transactional` 失效？ | 自调用、private/final、异常被吞、受检异常、异步线程。 |
| 默认回滚哪些异常？ | RuntimeException 和 Error；受检异常要 `rollbackFor`。 |
| 传播行为默认？ | REQUIRED：有事务加入，没有新建。 |
| 缓存一致性？ | Cache Aside：更新库后删缓存，延迟双删/binlog 补偿。 |

## 三、锁

| 问题 | 一句话答案 |
| --- | --- |
| InnoDB 锁的层次？ | 全局、表（含 MDL）、行；行锁有 S/X。 |
| 意向锁作用？ | 表级标记表内存在行锁，加表锁时不用逐行检查。 |
| Record/Gap/Next-Key？ | 记录锁 / 间隙锁 / 记录+前面间隙。 |
| Next-Key 解决什么？ | RR 当前读的范围幻读，阻止范围内插入。 |
| 锁加在哪里？ | 索引上；不是行本身。 |
| 没走索引会怎样？ | 全表扫描到的记录/间隙都锁，接近表锁。 |
| RC 和 RR 锁差异？ | RR 范围用 next-key；RC 基本无 gap（外键/唯一性除外）。 |
| 死锁四个条件？ | 互斥、持有并等待、不可剥夺、循环等待。 |
| 死锁怎么排查？ | `SHOW ENGINE INNODB STATUS`、`data_locks`、`data_lock_waits`。 |
| 死锁怎么避免？ | 固定顺序、短事务、走索引、减少范围锁、重试。 |
| `FOR UPDATE` 锁什么？ | 扫描到的索引记录和间隙；走主键等值锁一条。 |
| `NOWAIT` / `SKIP LOCKED`？ | 8.0 支持；拿不到锁立即返回/跳过，适合队列。 |
| 乐观锁？ | 版本号/CAS，`UPDATE ... WHERE version=?`，冲突重试。 |
| 悲观锁？ | `SELECT ... FOR UPDATE`，锁到提交，适合冲突多。 |
| 库存不超卖？ | `UPDATE stock SET stock=stock-1 WHERE id=? AND stock>=1`，看影响行数。 |
| MDL 是什么？ | 元数据锁；长事务持有共享 MDL 会阻塞 DDL。 |
| 自增锁默认模式？ | 8.0 默认 2（交错），配合 row binlog。 |
| 分布式锁？ | Redis/ZK；MySQL 行锁管不了跨实例。 |

## 四、分库分表

| 问题 | 一句话答案 |
| --- | --- |
| 什么时候分？ | 数据量/行大小/QPS/连接/磁盘到单机瓶颈；先索引、缓存、读写分离、归档。 |
| 分区表算分片吗？ | 不算；单实例内，便于管理，不解决单机瓶颈。 |
| 垂直拆分？ | 按业务分库或冷热字段分表。 |
| 水平拆分？ | 同结构按行拆到多表/多库。 |
| 分片键怎么选？ | 高基数、均匀、查询必带、业务稳定。 |
| 订单按 order_id 分片，怎么查我的订单？ | 基因法、映射表、异构索引（ES）、按 user_id 冗余。 |
| 路由算法？ | 取模（均匀、扩容难）、范围（扩容易、热点）、一致性哈希（迁移少）、映射表。 |
| 全局 ID？ | Snowflake、号段、Redis INCR；UUID 不适合做 InnoDB 主键。 |
| 跨片分页？ | 各片取 `offset+size` 归并；深分页用游标。 |
| 跨片 JOIN？ | 宽表冗余、ES、广播归并、基因法。 |
| 跨片聚合？ | 各片预聚合再汇总；`avg` 拆成 `sum/count`。 |
| 分布式事务？ | 避免跨片；Outbox/本地消息表最终一致；TCC/Saga/Seata；XA。 |
| 全局唯一约束？ | 数据库跨片保证不了；分片内唯一 + 独立唯一服务/Redis。 |
| 扩容？ | 双写 + 影子表 + 校验 + 切读；一致性哈希迁移少。 |
| 中间件？ | ShardingSphere-JDBC/Proxy、MyCat、Vitess；NewSQL：TiDB/OceanBase。 |
| 分库分表最大代价？ | 跨片查询、分布式事务、扩容迁移、运维复杂度。 |
| 你的项目要分吗？ | Orbit 目前不需要；按 user_id 是未来方向。 |

## 五、高频追问

| 追问 | 回答要点 |
| --- | --- |
| 为什么非叶子不存数据？ | 提高扇出、降低树高、减少磁盘 IO。 |
| 没有主键怎么办？ | 第一个非空唯一索引；否则隐藏 row_id。 |
| `a=? AND c=?` 走联合索引 `(a,b,c)` 吗？ | a 定位，c 最多 ICP 过滤，不能缩小范围/排序。 |
| 为什么 `SELECT *` 慢？ | 难覆盖、回表、传输无用列。 |
| 索引区分度低一定没用吗？ | 不一定；联合索引/覆盖索引仍可能有用。 |
| RR 下幻读绝对没有吗？ | 不是；快照读/当前读要分开，UPDATE 可能作用到新行。 |
| redo 和 binlog 为什么要 2PC？ | 保证崩溃恢复后两份日志一致。 |
| 为什么 RC 死锁少？ | gap lock 少，锁范围小。 |
| 长事务为什么阻塞 DDL？ | 一直持有共享 MDL，DDL 等排他 MDL。 |
| 分片后自增 ID 还能用吗？ | 只能保证分片内唯一；需要全局 ID 方案。 |

## 最后 5 分钟

- 一句话总结索引：**B+ 树 + 最左前缀 + 覆盖索引 + 看 EXPLAIN**。
- 一句话总结事务：**undo/redo + 隔离级别 + MVCC + 2PC**。
- 一句话总结锁：**锁索引，索引决定锁范围**。
- 一句话总结分片：**能不分就不分，分片键决定一切**。
- 不会的题：说清楚已知边界，再给验证方法，不硬编。
