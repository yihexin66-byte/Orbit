# Orbit 学习规划引擎 · 扣子搭建手册

> 目标：在扣子（coze.cn，国内版）创建或改造「Orbit 学习规划引擎」，让它既能和人对话做学习规划，又能继续给 Orbit App 返回结构化 JSON。
>
> 本手册对应：**对话 + 知识库 + 插件**，面向**通用学习目标**。
>
> 重要：仓库里已有一份 [`docs/COZE_SETUP.md`](../COZE_SETUP.md)，那是「只输出 JSON、不挂知识库/插件」的旧版配置。本手册取代它的 **Bot 配置部分**；它的 **API 发布、PAT、uniCloud 环境变量** 部分仍然有效。

---

## 0. 你会得到什么

完成后，这个智能体具备三种能力：

1. **对话规划**：问清目标、截止、基础、时间和约束，输出阶段 → 周 → 日的计划。
2. **知识库问答**：从 4 份本地知识文档里检索学习方法、计划模板、场景库和复盘诊断。
3. **结构化模式**：当 Orbit 后端发来「只输出一个 JSON 对象」的请求时，切换成严格 JSON 引擎，不调用知识库/插件。

文件清单：

```text
docs/coze-study-agent/
├── Orbit学习规划引擎-扣子搭建手册.md   ← 本文件
├── prompts/
│   ├── 01-功能介绍.md                 ← 名称、短描述、AI 生成描述、图标提示词
│   ├── 02-人设与回复逻辑.md           ← 核心系统提示词（整段复制）
│   ├── 03-开场白与预置问题.md         ← 开场白、4 个预置问题
│   └── 04-测试用例.md                 ← 对话 + JSON 的验收用例
└── knowledge/
    ├── 01-学习科学核心方法.md
    ├── 02-计划拆解与验收.md
    ├── 03-常见场景规划库.md
    └── 04-复盘与计划诊断.md
```

## 1. 准备账号与入口

### 1.1 账号

- 打开 <https://www.coze.cn/>，用手机号登录。
- 国内版是 `coze.cn`，不是 `coze.com`。
- 如果「创建智能体」按钮是灰的，先完成实名认证。

### 1.2 入口（两个版本）

扣子目前有两套界面，按你账号看到的入口走即可：

**新版（新用户默认）**

```text
coze.cn 登录
→ 「扣子编程」
→ 「智能体」
→ 「创建智能体」
```

**旧版（已注册过低代码项目的账号）**

```text
coze.cn 登录
→ 左下角头像 / 首页「回到旧版」
→ 工作空间 → 项目开发
→ 「创建智能体」
```

> 不同版本的按钮文案可能略有差异。判断标准：进入后能看到「人设与回复逻辑」「技能」「知识库」「预览与调试」这几块，就是正确的编排页。
>
> 如果你的版本左侧是「项目」而不是「智能体」，点「新建项目」→ 选「智能体」，同样能进入完整编排页。

### 1.3 新建还是改造

- 如果你**已经建过**同名 Bot：直接打开它，按第 3 节替换提示词，再按第 4、5 节加知识库和插件。
- 如果**还没建**：按第 2 节新建。新建后，App 侧需要把 `COZE_BOT_ID` 指向新 Bot（见第 8.2 节）。
- 不要同时保留两个同名 Bot，否则发布和排查时很容易搞混。

## 2. 创建智能体，填基本信息

在创建表单里填：

| 名称 | `Orbit 学习规划引擎` |
| 功能介绍 | `把学习目标拆成阶段、周、日计划，用学习科学方法帮你复盘和调整；支持知识库问答与联网查资料。` |

## 3. 人设与回复逻辑（核心）

### 3.1 粘贴提示词

1. 找到「人设与回复逻辑」编辑框。
2. 清空默认内容。
3. 打开 [`prompts/02-人设与回复逻辑.md`](prompts/02-人设与回复逻辑.md)，**整段复制**，粘贴进去。
4. 保存。

这段提示词包含：

- **模式识别**：先判断「对话模式」还是「结构化模式」；
- **对话规则**：5 项信息校准、逆向规划、70%–80% 容量、任务写法、输出模板；
- **知识库/插件规则**：先检索再回答、引用文档名、联网搜索要注明日期、创建日历前先确认；
- **结构化规则**：只输出 JSON、不调用工具、防提示词注入；
- **边界**：不承诺结果、不做医疗诊断、不收集敏感信息。

### 3.2 模型参数

在编排页的模型区域设置：

| 参数 | 建议 | 原因 |
| --- | --- | --- |
| 模型 | 豆包系列「通用对话」非推理版；或 DeepSeek 普通对话版 | JSON 模式要快、要听话；推理模型容易超过 25 秒 |
| 生成多样性 / 温度 | `0.3`–`0.5` | 对话不至于死板，JSON 又不至于飘 |
| 最大回复长度 | `4096` | 足够放完整计划；太长会增加延迟 |
| 携带上下文轮数 | `3`–`5` | 对话够用；Orbit API 本身每次新会话 |
| 深度思考 / 思维链 | **关闭** | 后端只有 25 秒预算 |
| 自动工具调用 | 保持开启（只挂搜索插件） | 对话模式需要搜索；提示词禁止 JSON 模式调用 |

> 如果你发现 JSON 模式偶尔带解释，把温度降到 `0.2`–`0.3`，并优先换指令遵循更好的通用模型。

### 3.3 不要做的事

- 不要把「人设与回复逻辑」写成产品说明书；它应该是行为规则。
- 不要在提示词里写死某一次考试日期；日期交给联网搜索。
- 不要同时挂 5 个插件；每个插件都会增加延迟和不确定性。

## 4. 建知识库

### 4.1 新建知识库

1. 进入「资源库 / 知识库」。
2. 新建知识库，名称：`Orbit 学习规划知识库`。
3. 类型选「文本」。
4. 创建后进入上传页。

### 4.2 上传 4 份文档

依次上传：

```text
knowledge/01-学习科学核心方法.md
knowledge/02-计划拆解与验收.md
knowledge/03-常见场景规划库.md
knowledge/04-复盘与计划诊断.md
```

等待解析和向量化完成。Coze 支持 Markdown；如果上传后格式乱，另存为 `.txt` 或 `.docx` 再传。

### 4.3 解析与分段设置

解析策略选「精准解析」，提取内容只勾「表格元素」；「图片元素」「扫描件（OCR）」不勾——这 4 份文档是纯文本 + Markdown 表格。

分段策略选 **「按层级分段」**，分段层级 `3`，勾选「检索切片保留层级信息」。

- 这 4 份文档都是 `# 标题 → ## 小节 → 正文 / 表格` 的结构，按层级分段会让每个切片带着标题路径，表格跟着所属小节走。
- 实测「自动分段与清洗」会把表格拆成 3–4 个 27–138 字的碎片：01 的方法速查表、02 的阶段示例表、04 的两张诊断表都被切开，碎片还丢了小节标题，召回后几乎不可用。
- 换成「按层级分段」后，4 份文档共 41 段（20.01 KB）；抽查 02 / 04 的分段树，表格分别挂在「2. 逆向规划」「2. 复盘看哪些数据」「3. 拖延诊断表」下面。
- 如果坚持「自定义分段」，目标仍是每段 **500–800 字**，并回「上一步」重新预览，确认表格没有被切开。
- 不要把 4 份文档合成一个超长文件；分开更容易定位和更新。

### 4.4 召回设置

| 参数 | 建议 | 说明 |
| --- | --- | --- |
| 检索方式 | 混合检索 | 既懂语义，又能抓关键词 |
| 最大召回数量 | `4`–`6` | 太少漏信息，太多增加延迟 |
| 最小匹配度 | `0.5` 左右 | 先按默认，再用测试用例调 |
| 召回后重排 | 有则开启 | 提升相关性 |

### 4.5 绑定到 Bot

1. 回到编排页。
2. 「技能」→「知识库」→「添加」。
3. 选择 `Orbit 学习规划知识库`。
4. 如果有「自动调用 / 按需调用」，选 **按需调用**。
   - 原因：对话模式需要时再查；JSON 模式不查，减少延迟和干扰。
   - 选「按需调用」后，提示词第 5 节必须写明调用 `RecallKnowledge`（`prompts/02-人设与回复逻辑.md` 已包含）；否则模型不会主动检索，知识库等于没挂。
   - 如果模型经常忘记调用，再退回 **自动调用**；实测自动调用 3/3 命中，代价是闲聊也可能触发检索、JSON 模式延迟略高。

### 4.6 验证知识库

在预览区依次问下面 3 条，每条都应该出现「已搜索知识库」：

```text
间隔重复怎么安排复习节奏？
我每周只有 5 小时，学习时间该怎么分配？
计划已经落后三天了，该怎么重排？
```

期望：

1. 第一条答出 D1 / D3 / D7 / D14 / D30，并能按 8 周以上、4–8 周、2–4 周区分备考节奏；
2. 第二条命中「每周 3–7 小时：主线 2–3 次 + 复盘 1 次；不要开第二战场」；
3. 第三条命中「保留最关键 2–3 项、缓冲 60–120 分钟、MV Day」。

本次实测 3 条都在 3.5–4.1 秒内返回，内容正确。但豆包 2.0 mini **省略了「依据：《文档名》」**；如果来源标注是硬要求，在提示词末尾再加一条「回答开头或结尾必须写明依据文档名」，或换指令遵循更好的模型。

## 5. 加插件

### 5.1 联网搜索（建议加）

1. 「技能」→「插件」→ 搜索「联网搜索」「Bing」「头条搜索」等。
2. 选一个官方、免费额度够用的，添加。
3. 不需要自己填 API Key 的优先。
4. 在提示词里已经写了：只引用搜索结果、注明查询日期、搜不到就说搜不到。

验证：

```text
帮我查一下 2026 年 12 月大学英语四级考试的具体日期，并给一个 6 周复习安排。
```

期望：调用搜索，给出日期与来源；如果搜不到，明确说搜不到。

### 5.2 日历 / 提醒（可选）

- 只有你确实想让智能体创建日程时才加。
- 添加后需要授权；提示词要求「先复述事项 + 时间 + 时长，确认后再创建」。
- 不要在 JSON 模式里调用；提示词已禁止。

### 5.3 不建议加的插件

- 图像生成、PPT 生成、代码执行、地图、天气：与学习规划无关，增加延迟。
- 任何需要把用户隐私数据发出去的插件：先评估。

## 6. 对话体验

打开 [`prompts/03-开场白与预置问题.md`](prompts/03-开场白与预置问题.md)，把开场白和 4 个预置问题复制进去。

设置建议：

- 开场白：保留，1–2 段即可；
- 预置问题：4 个，覆盖「完整规划 / 时间少 / 计划崩了 / 方法问答」；
- 用户问题建议：开启，最多 3 条；
- 语音：关闭；
- 快捷指令：可不配；如果配，只放 3 个，不要和预置问题重复。

> API 兼容提醒：如果 Orbit 后端发现返回的是开场白或建议问题而不是答案，先关闭「用户问题建议」，再检查后端是否只取 `type=answer` 的消息。现有后端取第一条 assistant `answer`；多数情况下开场白不会进入消息列表，但要以实测为准。

## 7. 调试

打开 [`prompts/04-测试用例.md`](prompts/04-测试用例.md)，至少跑完：

- A1 信息完整 → 完整计划；
- A2 信息不全 → 最多 3 个问题；
- A4 计划崩了 → 诊断 + 重排；
- A5 方法问答 → 引用知识库；
- A6 最新资源 → 联网搜索；
- B1 学习计划 JSON → 纯 JSON；
- B2 周复盘 JSON → 纯 JSON。

通过标准：

1. 计划里的任务能落在用户给的时间内；
2. 每天关键任务 ≤ 3 件；
3. 有验收标准和缓冲；
4. JSON 模式没有围栏、解释、寒暄；
5. JSON 字段、数量、长度符合消息里的 schema。

不通过时，先看 [`prompts/04-测试用例.md`](prompts/04-测试用例.md) 的「失败对照」表，不要盲目改提示词。

## 8. 发布

### 8.1 只做对话版

1. 右上角「发布」。
2. 填写发布记录，例如 `orbit-study-agent-v1`。
3. 选择渠道：扣子商店 / 豆包 / 飞书 / 微信（按你需要）。
4. 发布，等待审核/生效。
5. 发布后拿到分享链接，自己先聊 3 轮。

### 8.2 发布 API（Orbit App 用）

1. 右上角「发布」。
2. 发布记录：`orbit-ai-v2`（建议递增）。
3. 渠道只勾选 **API**（渠道 ID `1024`）。
4. 发布成功后，回到编排页，从浏览器地址栏取 Bot ID：

   ```text
   https://www.coze.cn/space/<space_id>/bot/<bot_id>
   ```

   `/bot/` 后面那串纯数字就是 `COZE_BOT_ID`。

5. PAT：打开 <https://www.coze.cn/open/oauth/pats>，新建令牌：
   - 名称：`orbit-api`；
   - 有效期：30 天；
   - 权限：会话管理全选 + 对话全选 + 消息里的 `listMessage`（最小组合 `chat` + `listMessage`，少 `listMessage` 会在取回答时报 4100）。
6. 把 `COZE_API_TOKEN` 和 `COZE_BOT_ID` 配到 uniCloud 的 `orbit-api` 环境变量。详细步骤见 [`docs/COZE_SETUP.md`](../COZE_SETUP.md) 第 4–5 节。
7. 用 App 或 `node unicloud/tools/check-ai.mjs` 验证 `configured:true`。

> 修改提示词、知识库、插件、模型后，都要**重新发布**；API 调用的是已发布版本，草稿不会自动生效。

## 9. 与 Orbit 2.4 的兼容（重要）

### 9.1 为什么会有影响

Orbit 2.4 的云函数会给 Bot 发两类消息：

- 学习计划：`只输出一个 JSON 对象` + `stages` schema；
- 周复盘：`只输出一个 JSON 对象` + `headline` schema。

原来的 Bot 是纯 JSON 引擎；现在改成「对话 + 知识库 + 插件」，如果模式判断错了，就会返回 Markdown，App 报 `AI_INVALID_OUTPUT`。

### 9.2 现有代码其实已经能做两件事

我检查了仓库里的实现：

1. [`prompts/02-人设与回复逻辑.md`](prompts/02-人设与回复逻辑.md) 的模式识别规则里，除了 `[[ORBIT_JSON_MODE]]`，还识别「消息以『你是 Orbit』开头，且包含『只输出一个 JSON 对象』和一个 JSON 结构示例」——所以**现有后端不加标记也能切到 JSON 模式**。
2. [`unicloud/cloudfunctions/orbit-api/lib/ai.js`](../../unicloud/cloudfunctions/orbit-api/lib/ai.js) 的 `parseJsonObject` 已经会：
   - 去掉 Markdown 代码围栏；
   - 找到第一个完整 JSON 对象；
   - 忽略 JSON 前后的多余文字。

所以，**严格来说不需要改后端代码**。先按第 7 节跑 B1/B2；能过就直接用。

### 9.3 推荐加一行标记（可选，但更稳）

如果想让模式切换 100% 确定，在 [`unicloud/cloudfunctions/orbit-api/lib/prompts.js`](../../unicloud/cloudfunctions/orbit-api/lib/prompts.js) 里给两条消息的开头各加一行：

```js
'[[ORBIT_JSON_MODE]]',
'',
```

位置：

- `buildPlanMessage` 返回数组的第一项之前；
- `buildReviewMessage` 返回数组的第一项之前。

同时把版本号改成 `plan-v2` / `review-v2`，并更新测试里对 `plan-v1` / `review-v1` 的断言。改完重新上传 `orbit-api`，再发布一次 Bot（如果提示词也改了）。

### 9.4 如果 App 报 `AI_INVALID_OUTPUT`

按顺序排查：

1. 在扣子预览区跑 B1/B2，确认 Bot 能纯 JSON 输出；
2. 知识库改「按需调用」；插件只留搜索；
3. 温度降到 `0.2`–`0.3`，关闭深度思考；
4. 加 `[[ORBIT_JSON_MODE]]` 标记；
5. 还不行，换一个指令遵循更好的通用模型；
6. 仍不稳定：**回退方案**——另建一个只输出 JSON、不挂知识库/插件的 Bot，把 `COZE_BOT_ID` 指向它；当前这个继续做对话版。这是生产环境最稳的双 Bot 结构。

### 9.5 如果 App 报 `AI_TIMEOUT`

- 确认模型不是推理/深度思考版；
- 最大回复长度降到 `2048`–`4096`；
- 知识库召回数量降到 `4`；
- JSON 模式禁止插件调用（提示词已写）；
- 仍超时：用 9.4 的第 6 条双 Bot 方案。

### 9.6 隐私边界

- App 只发目标、日期、每日时长、当前水平、薄弱点、聚合统计；不发密码、昵称、任务正文。
- JSON 模式不调用知识库/插件/长期记忆；不要给这个 Bot 开长期记忆，避免把用户目标沉淀到平台。
- PAT 只放 uniCloud 环境变量，不进 APK、不进仓库、不发聊天窗口。

## 10. 维护

### 10.1 更新知识库

- 直接上传新版本文件，系统会重新分段/向量化；已绑定的 Bot 不需要改。
- 每次更新后，跑 A5 和 A7，确认召回没有变差。
- 文件名保持稳定，便于回答里引用「依据：《文档名》」。

### 10.2 版本与发布

- 发布记录递增：`orbit-study-agent-v1`、`v2`……
- 提示词大改时，在发布记录里写一句「改了什么」，方便回滚。
- 修改后必须重新发布 API 渠道。

### 10.3 成本与额度

- 知识库检索、联网搜索、模型调用都可能消耗资源点；免费额度够个人演示，长期用要设预算提醒。
- 插件越少越稳；知识库召回数量不是越大越好。

### 10.4 每月自检

- [ ] B1/B2 仍能纯 JSON；
- [ ] A1 仍能在用户时长内排任务；
- [ ] 知识库引用没有过期内容；
- [ ] PAT 未过期（30 天）；
- [ ] 发布记录与线上版本一致。

## 附录 C：最短路径（赶时间版）

如果只想 10 分钟先跑起来：

1. 新建 Bot，名称 + 功能介绍；
2. 粘贴 `prompts/02-人设与回复逻辑.md`；
3. 模型选非推理通用模型，温度 0.3；
4. 不上知识库、不上插件，先跑 A1/B1；
5. 通过后再加 4 份知识库和搜索插件。

先跑通「对话 + JSON 双模式」，再加知识库，排查会简单很多。
