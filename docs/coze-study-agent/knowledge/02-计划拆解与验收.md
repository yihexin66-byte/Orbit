# 计划拆解与验收

> 用途：把「我要学好 X」变成可执行、可验收、可调整的计划。
> 核心：先定义终点，再倒推阶段，最后落到每天能做的动作。

## 1. 目标校准：从愿望到验收

一个可规划的目标至少包含四件事：

1. **终点**：达到什么程度算完成？例如「能独立做出带登录和 CRUD 的后端项目」，而不是「学好 Java」。
2. **期限**：具体日期或周数。
3. **基础**：现在会什么、上次卡在哪。
4. **投入**：每周能稳定投入多少小时，哪些天。

把目标改写成一句话：

> 在【期限】前，用每周【X 小时】，从【基础】达到【可演示/可测量的结果】。

如果写不出「可测量的结果」，先做一个 30 分钟的小任务来定义它，例如找一份样题、看一个项目示例、做一次自测。

## 2. 逆向规划：从截止日倒推

步骤：

1. 写下截止日和今天，算出可用周数。
2. 把总目标拆成 3–5 个阶段，每个阶段有**一个主要能力**和**一个验收标准**。
3. 给每个阶段分配时间，最后留出 10%–20% 的缓冲。
4. 把当前阶段拆成周任务，再把本周任务落到具体日期。
5. 只详细排本周；后面的阶段保持粗粒度，每周再滚动细化。

阶段示例（8 周入门后端）：

| 阶段 | 时间 | 主要能力 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 第 1–2 周 | 语法与数据库基础 | 能独立写出 CRUD 的 SQL 和 20 道基础题 |
| 2 | 第 3–4 周 | Web 接口与分层 | 能跑通一个带参数校验的 REST 接口 |
| 3 | 第 5–6 周 | 登录与权限 | 能实现注册/登录/鉴权，并写 3 个测试 |
| 4 | 第 7–8 周 | 整合与演示 | 能演示完整项目，讲清 3 个关键取舍 |

## 3. 任务写法：动词 + 对象 + 时长 + 产出 + 验收

不合格的任务：

- 学 Spring Boot；
- 复习英语；
- 看网课。

合格的任务：

- 跟做一节 30 分钟的 Spring Boot 控制器教程，自己重写一遍，能解释 `@RestController` 的作用；
- 做 20 道定语从句选择题，把错题按「关系词/先行词/例外」分类，正确率写到 80%；
- 读 10 页教材，合书画出本章结构图，能讲出 3 个核心概念。

任务卡模板：

```text
任务：动词 + 对象
时长：25 / 45 / 60 / 90 分钟
产出：一段代码 / 一张图 / 一组题 / 一段录音 / 一篇摘要
验收：正确率 / 能否复述 / 能否演示 / 能否通过测试
```

## 4. 容量：按 70%–80% 排

- 先算「理想容量」：每周可用小时数 × 0.8。
- 再留一个缓冲时段（例如周日下午）处理落后任务。
- 不要把 7 天排满；至少留半天完全休息或机动。
- 每天最多 3 件关键任务；其余是可选任务。
- 新计划的第一周再打 8 折，用来校准自己的真实速度。

## 5. 最小可行日（MV Day）

给每个学习日定义一个「再忙也能完成」的最低版本：

- 10 分钟：复习 10 张卡 / 做 3 道题 / 读 2 页并写 1 句话；
- 20 分钟：做一组 5 题并订正 / 跟做一个小练习；
- 目标是保持连续性，不是替代正常计划。

规则：

- 状态差时启动 MV Day，不补昨天的债；
- 连续 2 天只完成 MV Day，周末重排，而不是加倍；
- MV Day 也算完成，不产生「我又失败了」的叙事。

## 6. 缓冲与追赶规则

1. 每周预留 1 个缓冲块（60–120 分钟）。
2. 落后 1 天：用缓冲块补，不挤占休息。
3. 落后 2–3 天：砍掉低优先级任务，保留阶段验收任务。
4. 落后超过 3 天：重排本周，不追全部旧任务；只保留「对验收最关键」的 2–3 项。
5. 提前完成：把时间加给薄弱点或做一次自测，不要无限加新任务。

## 7. 每周计划模板

```markdown
## 本周目标
- 只写 1 个本周必须达成的验收结果。

## 本周关键任务
| 日期 | 任务 | 时长 | 产出/验收 |
| --- | --- | --- | --- |
| 周一 | ... | 45 | ... |
| 周三 | ... | 60 | ... |
| 周六 | ... | 90 | ... |

## 缓冲
- 周日 14:00–16:00：补落后任务 / 周复盘。

## 最小可行日
- 10 分钟版本：...

## 周末复盘
- 完成率：...
- 卡点：...
- 下周只改一件事：...
```

## 8. 验收标准怎么写

好的验收标准是可观察的：

- 「能不看资料写出 3 个核心概念，并各举一个例子」；
- 「20 道题正确率 ≥ 80%，错题能说出错误类型」；
- 「能独立跑通接口，Postman 返回 200，并解释参数校验在哪一层」；
- 「能 3 分钟讲清项目架构，回答 2 个追问」。

不好的验收标准：

- 「理解了」；
- 「看完了」；
- 「感觉会了」；
- 「学了很多」。

- [ ] 每天关键任务 ≤ 3 件吗？
- [ ] 每周留了缓冲吗？
- [ ] 有最小可行日吗？
- [ ] 落后时的处理规则明确吗？
- [ ] 第一周是否按 80% 容量试跑？
