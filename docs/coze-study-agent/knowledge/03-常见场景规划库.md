# 常见场景规划库

> 用途：给不同学习目标提供可复用的节奏、核心动作、验收和常见坑。
> 使用方式：先匹配场景，再按用户的时间预算缩放；不要直接照搬整张表。

## 1. 考试备考（四六级、期末、证书、专升本）

**节奏**：
- 8 周以上：基础 → 题型 → 套题 → 冲刺，四段式；
- 4–8 周：题型 → 套题 → 错题回炉；
- 2–4 周：真题 + 错题 + 高频考点，不铺新资料。

**核心动作**：
1. 先做 1 套真题定位，不按「从头学」开始；
2. 按题型建错题本，标注错误类型（不会 / 看错 / 时间不够 / 方法不对）；
3. 每周 1–2 套限时套题，做完必须订正；
4. 高频考点用主动回忆 + 间隔重复；
5. 考前一周只做错题和熟题，不刷新难题。

**验收**：套题分数趋势、错题重复率下降、限时完成率。

**常见坑**：只听课不做题；只刷题不订正；资料越买越多；考前熬夜。

## 2. 语言学习（英语、日语等）

**节奏**：每天 30–60 分钟，输入与输出交替；每周一次复盘。

**核心动作**：
- 词汇：少量多次 + 间隔重复；新词放进句子；
- 听力：精听一段（听写/复述）+ 泛听；
- 阅读：精读一段，标主干和生词，做摘要；
- 口语：录音 → 对照 → 重录；每周 2–3 次；
- 写作：每周 1 篇，批改后重写一遍。

**验收**：能复述一段材料；录音错误率下降；写作重写后错误减少。

**常见坑**：只背单词不输入；只看看美剧不精听；不敢开口；每天换材料。

## 3. 编程 / 技术技能

**节奏**：概念 20% + 动手 60% + 复盘 20%；以项目里程碑驱动。

**核心动作**：
1. 定义一个最小可演示项目（MVP）；
2. 拆 3–5 个里程碑，每个有可运行产出；
3. 每个知识点至少写一次自己的例子；
4. 遇到 bug 先记录现象、假设、验证，再搜索；
5. 每周做一次代码复盘：能讲清目录结构、关键取舍、一个失败方案。

**验收**：能跑、能改、能讲；不是「跟着视频敲完」。

**常见坑**：教程地狱；只收藏不写；一开始就做大项目；不写测试；不读报错。

## 4. 读书 / 通识学习

**节奏**：每周 1 本书或 2–3 个章节；读后必须有输出。

**核心动作**：
- 先看目录和结论，提出问题；
- 读一章，合书写 3 句话摘要；
- 每周做一张概念图或 300 字笔记；
- 每月把一本书讲给别人听（或录 3 分钟音频）。

**验收**：能不看书画出结构；能回答自己提出的问题；能讲清一个反例。

**常见坑**：只划线不输出；追求页数；同时读很多本；不做回顾。

## 5. 毕业设计 / 课程项目

**节奏**：按里程碑倒推；每周与导师/队友同步一次。

**核心动作**：
1. 先写清问题、范围、交付物和不做什么；
2. 拆里程碑：调研 → 原型 → 主功能 → 测试 → 文档/答辩；
3. 每周产出一个可演示增量；
4. 风险前置：先验证最难的技术点；
5. 答辩材料提前两周开始，按「问题—方法—证据—限制」组织。

**验收**：每两周有可演示版本；关键风险有验证记录；答辩能讲清取舍。

**常见坑**：范围过大；最后才集成；不记录失败方案；文档拖到最后。

## 6. 面试 / 求职准备

**节奏**：4–8 周；技术 + 项目 + 表达三条线并行。

**核心动作**：
- 技术：按岗位 JD 列高频题，主动回忆 + 白板/口述；
- 项目：每个项目准备「背景—我的职责—难点—取舍—结果—如果重做」；
- 表达：每周 2 次模拟面试，录音回听；
- 复盘：把答不上的问题整理成下一周清单；
- 投递：每周固定数量，记录反馈。

**验收**：能在 2 分钟内讲清一个项目；高频题能口述；模拟面试评分上升。

**常见坑**：只刷题不讲项目；背答案不理解；不记录面试反馈；投递无节奏。

## 7. 场景缩放规则

| 可用时间 | 建议 |
| --- | --- |
| 每周 < 3 小时 | 只保留 1 个主线 + 1 个维持任务；接受更长周期 |
| 每周 3–7 小时 | 主线 2–3 次 + 复盘 1 次；不要开第二战场 |
| 每周 8–15 小时 | 主线 + 练习 + 每周套题/项目增量 |
| 每周 > 15 小时 | 必须安排休息和缓冲；警惕用时长代替反馈 |

## 8. 选择场景时的三个问题

1. 这个目标最终要「产出什么」？（分数、作品、表达、证书）
2. 现在最缺的是「知识、练习、反馈、还是时间」？
3. 如果只能保留一个动作，哪个动作最接近验收？

先回答这三个问题，再选场景模板。
